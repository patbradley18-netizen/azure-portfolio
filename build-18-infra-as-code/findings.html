A template that changes nothing: converging a hand-built resource group onto Bicep, proving it, and gating it

Builds #1–#17 were created with the CLI; build #10 wrote a Bicep template of the result and every build since appended to it, but it had never been deployed. This build made the template converge: a first real deployment onto the live group, a second one to prove idempotence, a throw-away group to prove create → verify → delete, and a CI gate that fails on any Create or Delete. Anchor phrase: a template that changes nothing is the proof.

What the first what-if said, and what was wrong with it

Before the fixes: 5 Create, 12 Modify, 12 NoChange. Every Create was a role assignment whose template name (guid() of its seeds) could never equal the name Azure gave it at CLI time — so the template was about to add five duplicates. The fix is to adopt the live names as literals. Most Modify rows were server defaults the template did not state (API Management protocol flags, Search network rules, container encryption scope), one wrong container name, and an app-settings block that would have replaced the Function host's own settings — rewritten as a union(list(…)) merge in a module, because the parent template cannot list a config it also deploys (circular dependency, twice).

The ephemeral proof

A second template with the free pieces of the pattern — storage with shared-key access off, two containers, a queue, a Key Vault in RBAC mode, a user-assigned identity with two scoped roles, an Event Grid system topic — deployed into rg-azportfolio-iac-test, verified by a script against the live resources, and deleted (vault purged) in the same run. What this cannot say

The template is a record of a group that was built by hand; it converges on that group, it did not create it. Three things remain outside it on purpose: the operator's own role assignments, the secrets (a Key Vault reference and run-time parameters only), and the loader container group (see above). The roles that build #14 granted to its identities on the storage account are not in the template yet; what-if cannot see what the template does not mention.
