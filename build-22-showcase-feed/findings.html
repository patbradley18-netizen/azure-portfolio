The showcase feed: every build's figures as plain JSON tables, so another tool can draw them

Nineteen builds each ended with a page here. The figures on those pages are baked into HTML; nothing else can draw them. This build publishes the data behind them as static JSON on the same site: one small table per series, a manifest per build, one index. No API, no key, no quota, no new resource. Anything on any origin can read them, because a CORS rule says so and because every file passes the feed's refusal (no email address, no GUID, no document text). Anchor phrase: Azure feeds, Kiln draws, never the other way.

How to read it

https://stazportfoliob1.z14.web.core.windows.net/showcase/index.json ─► builds[]: build, title, anchor, page, readme, image, manifest └─► https://stazportfoliob1.z14.web.core.windows.net/showcase/build-NN-name.json ─► series[]: id, title, columns, n, bytes, url └─► https://stazportfoliob1.z14.web.core.windows.net/showcase/build-NN-name/<id>.json ─► columns[] + rows[][] (schema azportfolio-showcase/1)

Every table has the same four keys that matter: columns, rows, n, title. Rows are arrays in column order. The shape is versioned; a reader can pin schema.

What the feed refuses, and what it drops

A file that contains an email address or a GUID stops the build. Documents are not figures: any table with a cell over 300 characters is skipped (build #5's press-release text, for one). A column whose values are GUIDs is dropped from the table rather than failing the build: 6 columns went that way.

Build #10's county table is the map; a reader that only wants the state summary fetches the state table instead. Nothing is paginated — the biggest file is under 1.5 MB and the site caches it.

How it stays current

The site deploy runs build_feed.py on every push and uploads showcase/ with the pages. Its live check fetches the index with a foreign Origin header and fails the deploy if the CORS header is missing. The CORS rule is one resource in main.bicep (blob service, GET/HEAD/OPTIONS, any origin), deployed through the #18 template: what-if showed that one Modify and nothing else.

Why any origin: the data is public by construction and CORS is a browser rule, not an access grant; the private containers on the same account still require a token. Kiln Studio's Electron renderer reads from a file:// or app origin, which no named-origin rule would match.

Cost: $0 (static files on the storage account that already hosts the site; one CORS rule). Found on the way: build #11 had no README in the repo; it has one now. Non-commercial learning project. Built with Claude.
