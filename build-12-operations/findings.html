Before the bill: the free SQL limit, the Functions, and an alert that proved itself

An operations page for a portfolio that runs on free tiers. The unit that actually bites is the free Azure SQL database's 100,000 vCore-seconds a month; a metric alert now emails before that line, and it fired once on purpose to prove the path works. The rest is KQL over the Log Analytics workspace the Function wizard created: run history, the one failure, and how little gets ingested. Anchor phrase: a number, a threshold, an email. Expand any query to read the KQL.

The free SQL limit

The free Azure SQL database has used 9,459 of 100,000 vCore-seconds this month (9.5%) across twelve builds; 91,638 remain. The metric is emitted only while the database is awake — 10 hourly points in the last 30 days, between 2026-10-14 and 2026-10-17 — which is itself the clearest picture of how the serverless tier spends: nothing while paused, a few thousand seconds per working evening.

Metric free_amount_consumed on the database, hourly maximum, as emitted; points are evenly spaced, not to time scale; snapshot taken 2026-10-17 03:23 UTC. The database auto-pauses when the free amount is exhausted (set in build #2, OI-05), so the alert is a warning before a pause, not before a charge.

The alert, and its proof

The alert rule alert-sql-free-limit watches free_amount_consumed (Maximum over PT1H, every PT15M) and emails action group ag-azportfolio-ops. Set first to 9,000 so it would fire now, it fired at 2026-10-17 03:20 UTC (Sev2, target aid) and the email arrived. It now sits at 80,000 — 80% of the month's free allowance — so the warning lands before the database auto-pauses for the month, not after.

Metric alert rules are free for the first ten monitored time series per month; this is one. Action-group email is free for the first 1,000 a month. No log-search alert rules were created (they bill per rule). The rule, the action group and the two Application Insights components are now in the portfolio's Bicep (build #10's infra), which what-if reports as no change.

3 Function invocations are in the workspace so far (2 succeeded), all manual test runs: the first scheduled runs are Saturday 12:00 UTC (build #2) and Monday 06:00 UTC (build #1). What this cannot say

Three invocations are not a run history; the scheduled runs begin this weekend and the workbook is where they will accumulate. The free-limit metric is silent while the database is paused, so a flat line means asleep, not idle. An alert that fired at 9,000 proves the path, not the threshold: 80,000 has never been reached and the warning has never been needed. Application Insights sampling can make request counts estimates; it was off here. Cost figures are tier allowances, not an invoice — Cost Management is the invoice.
